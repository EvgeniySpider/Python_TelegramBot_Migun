# 📅 Telegram Calendar & Event Management System

Высокопроизводительный асинхронный Telegram-бот с интерактивным календарем, системой планирования встреч, полнофункциональным REST API и панелью администратора.

Проект разработан на базе современного стека **Python 3.12**, **python-telegram-bot 21+**, **Django 6**, **Django REST Framework** и **asyncpg** для работы с СУБД **PostgreSQL**.

---

## 🛠 Технологический стек

- **Язык:** Python 3.12
- **Telegram Bot API:** `python-telegram-bot 21.x` (полностью асинхронный, FSM `ConversationHandler`)
- **Web-фреймворк и ORM:** Django 6.x
- **REST API:** Django REST Framework (DRF)
- **База данных:** PostgreSQL 16
- **Низкоуровневый асинхронный драйвер БД:** `asyncpg` (пул соединений для мгновенных запросов бота)
- **Управление зависимостями:** Poetry
- **Контейнеризация:** Docker, Docker Compose (Multi-stage build)
- **Тестирование:** `pytest`, `pytest-asyncio`, `pytest-django` (192 тестов)
- **Линтинг и типизация:** Ruff (PEP 8, isort, pyupgrade), Mypy (строгий статический анализ)

## 🚀 Ключевые возможности и архитектура

### 1. 🗓 Интерактивный календарь в Telegram
- **Динамическая генерация матрицы месяца:** Инлайн-сетка календаря с индикацией занятости дней:
  - 🔴 — день занят полностью (событие «Весь день» или сумма интервалов >= 24ч);
  - 🟡 — день занят частично;
  - ⚪ — подсвечиваемый день при переносе даты мероприятия.
- **Удобная навигация:** Мгновенное переключение месяцев стрелками `« Пред` / `След »` без мерцания интерфейса.
- **Машина состояний (FSM):** Изолированные сессии диалогов для каждого пользователя.

### 2. 📝 Управление событиями (CRUD)
- **Три типа событий:**
  - ☀️ **Весь день (`all_day`)** — блокирует день целиком, защищен от наложения других интервалов.
  - ⏱️ **Точное время (`exact`)** — синтаксический сахар для интервалов с автоматическим расчетом +30 минут к окончанию. Включает обрезку времени в конце суток (события позже 23:29 завершаются в 23:59, создание событий позже 23:58 блокируется во избежание нулевой длительности).
  - ⏳ **Интервал (`interval`)** — точное указание начала и конца мероприятия (`ЧЧ:ММ-ЧЧ:ММ`).
- **Контроль коллизий и пересечений:** Математическая проверка интервалов в PostgreSQL на лету (`start_1 < end_2 AND end_1 > start_2`).
- **Умная мутация типов (API):** Если пользователь решает добавить время к событию «Весь день» через PATCH-запрос, система автоматически конвертирует его в exact или interval с полным перерасчетом коллизий.
- **Редактирование:** Пошаговое изменение названия, описания, времени, приватности и перенос мероприятия на другую дату с повторной проверкой конфликтов занятости.
- **Удаление:** Одиночное удаление (инлайн-кнопками или вводом номера), а также групповая очистка всех дел на выбранную дату с экраном подтверждения.

### 3. 🤝 Система совместных встреч (Appointments)
- **Приглашение участников:** Назначение встреч другим пользователям по их Telegram ID.
- **Проверка доступности гостя:** Алгоритм `check_user_availability` проверяет личное расписание гостя и его другие подтверждённые встречи перед отправкой приглашения.
- **Интерактивные инвайты:** Гость получает уведомление с кнопками `✅ Принять` и `❌ Отклонить`.
- **Синхронизация расписаний:** При подтверждении копия события автоматически создается в календаре гостя.
- **Каскадная отмена:** При отмене встречи организатором или отказе гостя расписания синхронно очищаются, а вторая сторона получает Telegram-уведомление (в том числе в фоновом потоке при удалении через REST API).
- **Общие события:** Возможность переключения приватности (`is_public`) и просмотра публичных заметок любого зарегистрированного пользователя.

### 4. 🔑 REST API (Django REST Framework)
- **Кастомная токен-аутентификация:** Модель `BotTokenAuthentication` с ограничением срока жизни ключа (`API_TOKEN_LIFETIME_MINUTES`).
- **Динамическая генерация ключей:** Команда `/api_token` в боте генерирует персональный токен доступа с настраиваемым сроком жизни (TTL). Если срок истек — API автоматически отсекает запросы с 401 Unauthorized.
- **Защита целостности данных (IDOR):** Полная изоляция QuerySet на уровне DRF. Пользователь имеет доступ строго к своим приватным записям, попытки изменить чужое событие жестко отбиваются 404 Not Found.
- **Эндпоинты:**
  - `GET /api/events/` — список всех публичных событий.
  - `GET /api/events/<telegram_id>/` — публичные события выбранного пользователя.
  - `GET, POST /api/my-events/` — чтение и создание личных событий авторизованного пользователя.
  - `GET, PUT, PATCH, DELETE /api/my-events/<id>/` — детальный просмотр, полное/частичное обновление и удаление своего события.

### 5. 📥 Экспорт данных
- `/exportjson` — прямая выгрузка всех дел пользователя в формате структурированного JSON-файла.
- `/exportcsv` — генерация таблицы CSV с разделителем `;` и кодировкой `utf-8-sig` (с BOM) для корректного открытия в Microsoft Excel на русском языке без искажения символов.

### 6. 📊 Статистика и панель администратора Django
- Модель `BotStatistics` агрегирует метрики по суткам: количество новых пользователей, клики по календарю, созданные события (по типам), отредактированные и удаленные записи.
- Персональные счетчики активности в модели `User`.
- Настроенная админка Django (`/admin/`) с фильтрами, группировкой полей и readonly-режимом для исторических метрик.

## ⚡ Быстрый старт и развёртывание

### Вариант 1. Запуск через Docker Compose (Рекомендуемый)

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/EvgeniySpider/Python_TelegramBot_Migun.git
   cd Python_TelegramBot_Migun
   ```

2. **Создайте файл конфигурации `.env`:**
   Скопируйте шаблон:
   ```bash
   cp .env.local.template .env
   ```
   Укажите ваш реальный токен бота `TELEGRAM_API_KEY` (полученный у `@BotFather`) и ваш `TELEGRAM_ID` (узнать можно у `@userinfobot`).

3. **Соберите и запустите контейнеры:**
   ```bash
   docker compose up --build -d
   ```
   Будут запущены 3 сервиса:
   - `db` — PostgreSQL 16 (порт `5444` наружу, `5432` внутри сети);
   - `web` — Django / DRF API (доступен по адресу `http://localhost:8000`);
   - `bot` — асинхронный процесс Telegram-бота.

4. **Примените миграции базы данных:**
   ```bash
   docker compose exec web python manage.py migrate
   ```

5. **Создайте суперпользователя для админки (опционально):**
   ```bash
   docker compose exec web python manage.py createsuperuser
   ```

---

### Вариант 2. Локальный запуск для разработки

1. **Установите зависимости через Poetry:**
   ```bash
   poetry install
   ```

2. **Запустите PostgreSQL** (например, через `docker compose up -d db`).

3. **Примените миграции:**
   ```bash
   poetry run python manage.py migrate
   ```

4. **Заполните базу тестовыми событиями (сидер):**
   ```bash
   poetry run python -m app.infra.postgres.seed_events
   ```

5. **Запустите Django Web-сервер и Бот в раздельных терминалах:**
   ```bash
   # Терминал 1: REST API
   poetry run python manage.py runserver 127.0.0.1:8000

   # Терминал 2: Telegram-бот
   poetry run python -m app.main
   ```
